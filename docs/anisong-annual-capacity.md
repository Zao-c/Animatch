# 年度 OP / ED 曲单容量

基于 PR #11，曲单上限由 64 提高为 1000。使用同一 MAX_TRACKS 校验手动导入、网易云按钮、批量队列、参赛选择和 Tier 排序，修复残留硬编码。JSON 请求上限从 16 KiB 改为 128 KiB，足以提交 1000 个 UUID 的完整排序，仍拒绝过大请求。本地上传总量从 250 MiB 提高为 2 GiB；单音频仍为 20 MiB。公共音频池与 COS 配额保持现有配置。

歌曲墙每页最多挂载 48 张卡片和播放器；搜索、类型、年份、季度筛选及批量选择仍作用于完整筛选结果，翻页不会清除已选歌曲。

128 首以内继续使用原来的完整候选配对；更大的曲单每轮从全体参赛歌曲中选择至多 128 个候选，兼顾低曝光、随机探索和全排名区间，再调用原有评分配对器。这改变大曲单的选对策略，不改变投票结果、Elo 更新或 Tier 计算。候选选择使用现有可重放随机种子，同一进度刷新不会随机换对。不会预下载整个曲单音频。

PNG 以每页至多 150 首分张，避免 1000 首同档导致超长画布及高内存占用。文件名标记页码，界面显示多文件下载提示；浏览器可能需要用户允许多文件下载。JSON 与分享快照仍包含完整榜单。原有每曲单 5000 条操作记录上限未变。

## 验证

仅使用本机隔离的 anisong-dev-db 和合成数据，不修改生产用户曲单。

- 新增容量边界测试：第 65 / 1000 首允许，第 1001 首拒绝；满额可编辑已有歌曲。
- 1000 首完整同档排序、128 候选上限、低曝光候选、确定性重放、参赛范围与超过 64 首的曝光覆盖通过。
- 1000 个 UUID 的排序请求允许，超 128 KiB 仍拒绝；原有授权与版本冲突校验未修改。
- PNG 分页验证没有遗漏或重复歌曲，单档与待比较区 1000 首均生成 7 页。
- Chromium 实测在 390 / 1280px 每页仅 48 张歌曲卡片；翻页正常，全文搜索能命中第 1000 首，无横向溢出。
- 手动表单实际添加第 65 首并保存成功；1000 首曲单实际 Match 投票、Tier 移动最后一首、保存后刷新均通过；第 1001 首 API 拒绝。
- 浏览器实际触发并接收 7 张 PNG 下载，无 pageerror。此次未重验真实网易云 / iTunes 上游，不能将合成数据验收视为真实服务验收。
- 全量 161 文件 / 1698 测试通过；TypeScript、Lint、Docker 生产构建、git diff --check 通过。

部署只替换 app 容器，保留数据库与媒体卷；数据库备份及 rollback-pre-annual 镜像供回滚。没有 schema 或迁移文件变化。此分支包含上一轮 PR #11 的 UI 修复；不直接合并 PR 或推送 main。

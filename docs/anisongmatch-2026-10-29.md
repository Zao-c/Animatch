# AnisongMatch 第一版

入口：`/anisong`，导航栏「音乐对决」。实现分支：`feature/anisongmatch`。封面与交互迭代见[优化方案与验证](anisongmatch-cover-ui-plan.md)。

## 可用流程

1. 登录现有 AniMatch 账号，创建「2026 秋季 OP」「摇滚 ED」等个人曲单。
2. 添加歌名、歌手、所属动画、OP / ED / 插入曲、年份、季度和风格标签。可上传自己的音频，或填写可公开访问的 HTTPS 音频直链；也可暂不添加音频，凭印象比较。
3. 设定试听起点和长度（默认30秒，可选5–90秒）。选择筛选结果参赛，或全曲单参赛。
4. 左右选择、平局、跳过、未听过；支持键盘1/2/3/4和撤回。未听过的歌曲可在曲单中恢复。
5. 自动生成完整 S/A/B/C/D Tier List；待比较单独展示。可手动指定档位，或恢复自动分档。
6. 导出 PNG / 榜单 JSON，或者生成公开分享快照。分享包含歌曲封面，不含音频、音频地址和账号信息；更新快照需主动点击，关闭分享后旧链接失效。
7. 编辑或移除歌曲；删除曲单会同时删除私有音频与分享链接。

音频先在浏览器中试听，播放器互斥，换题或离开视图会停止。直链不经服务器代理。上传音频在私有目录中，通过检查曲单所有者的 GET / HEAD 路由播放；支持 HTTP Range，方便移动端加载和拖动。

## 排名与数据边界

- 使用原有 `updateElo`、`pickNextPair`、`buildTierList`、`buildRankingProgress`，不改动画玩法。
- 独立 `SongBoard` 数据表，一份曲单对应一个人的音乐对决。歌曲、选择历史、参赛范围、手动档位一起以 revision 保存。
- 每次从选择历史重算分数；撤回移除最后一步并重放历史。跳过和未听过不计入有效比较。
- 切换筛选范围后，只使用当前参赛歌曲相互之间的比较证据；恢复范围可重新使用原有历史。
- 相同自动评分共用该组中间位置对应的档位。未比较歌曲不会被强行分档；手动档位不改 Elo 或对决记录。
- 分档是曲单内相对偏好，不是歌曲绝对质量评价。原有进度阶段按比较数量计算，UI 明示其并非统计置信度。
- 数据写入使用 revision 条件更新；冲突返回409。重复提交同一投票 eventId 不会重复计分。网络结果不确定时，界面要求先重新载入已保存状态。
- 每曲单最多64首，每音频20 MB，每曲单上传总量250 MB，每账号最多30份曲单，每曲单最多5000次对决操作。
- 原始请求体按实际字节限制，文件识别检查签名。支持 MP3、M4A（M4A/M4B容器）、WAV、OGG、FLAC；具体解码能力仍由浏览器决定，失败时可跳过或更换音频。

## 对 MusicCup 的调研

依据 [MusicCup 的公开介绍](https://musiccup.app/?lang=hans)，其流程包含歌手搜索、热门/随机/自选曲目、iTunes 试听、小组赛、复活赛、淘汰赛和冠军分享图，公开排行榜汇总赛果。

本次可读取公开页面；尝试直接读取前端脚本入口时服务器返回403，因此没有声称验证过其内部接口、具体计分实现或运行时网络行为，也没有复制其私有接口、代码或素材。AniMatch 的音乐玩法使用自己的持续配对和个人分档，不采用冠军淘汰制。公开社区音乐榜单未在本版本实现。

## 留待确认的第三方音源

按本次要求，第三方 API 接入留待后续确定；本版完整可用的音源是上传文件和自有直链，没有伪装为可用的曲库搜索按钮。

| 方向 | 已知情况 | 后续决策 |
| --- | --- | --- |
| iTunes Search API | 可搜索音乐元数据与试听地址，但其[官方文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html)对试听有推广用途、商店链接、署名及不得下载缓存等条件 | 确认这种音乐比较场景的使用条件和商店地区，再接搜索适配器；不能直接因为 MusicCup 使用就认定可照搬 |
| 网易云音乐 | 本次没有调用第三方逆向接口或使用用户 Cookie | 确定允许使用的服务、凭据及部署方式；不把非官方接口当成稳定开放 API |
| 自动季度 OP / ED 曲库 | 当前季度/类型/动画关系由用户填写；不提供虚构的新番歌曲数据 | 确定动画主题曲元数据来源与音源的匹配规则，再添加批量导入和搜歌 |

已保持歌曲元数据、音源、播放器与排名分离，未来可增加有来源标识的 provider 适配层，而无需改动画表和对决引擎。当前没有云端搜歌、跨用户共享音频池、社区音乐聚合榜或音频转码。

## 部署准备

本次开发和浏览器验证使用独立 PostgreSQL 数据库，未执行生产迁移或重启生产服务。

- 新增迁移：`20261029000000_anisongmatch`，只添加 `SongBoard` 表、索引和关联用户的外键。
- 已有生产库：按现有部署流程备份后执行 `prisma migrate deploy`，不能使用 `db push`。
- 新增 Docker 卷 `anisong_audio:/app/data/anisong-audio`。该目录不得放入 `public` 或配置为静态资源目录；必须和数据库一起备份、恢复。
- 本地默认目录为 `data/anisong-audio`；可通过 `ANISONG_AUDIO_DIR` 覆盖，已加入 `.gitignore`。
- 反向代理需允许至少26 MB的 multipart 请求（例如 Nginx `client_max_body_size 26m`），容纳20 MB音频和5 MB封面以及表单开销；应用分别限制文件大小。
- 若回退版本，保留音频卷和新增数据表；旧动画功能不依赖音乐表。不得用 `docker compose down -v` 删除数据卷。

## 验证

- 新增单元测试覆盖：计分重放、平局、跳过、撤回、未听过、候选范围、曝光配对、手动档位、分享剥离音频、请求体上限、文件签名、Range 与元数据校验。
- 在独立空库完成 Prisma schema 初始化，用真实登录、真实上传与真实 API 进行 Chromium 浏览器验证；测试音频为本地生成的正弦波，不使用音乐版权素材。
- 浏览器检查包括：创建曲单、上传、互斥播放、试听终点、投票、撤回、刷新恢复、手动分档、PNG下载、匿名分享访问、撤销分享、类型筛选、旧 revision 冲突、无效文件、跨用户读取限制、投票重试、手机无横向溢出。
- 定向测试共34项通过（音乐引擎6项、音频和校验5项、音乐持久化8项，以及原有 Elo、配对、导航回归15项）；全项目 ESLint、TypeScript 检查和 `pnpm build` 均通过。
- 新增迁移 SQL 在隔离 PostgreSQL schema 中执行成功，使用事务回滚测试数据；没有在生产库执行。
- 构建后的 `next start` 真实接口额外验证：编辑保留原音频、替换后清理旧文件、并发写入只成功一个、普通投票不改已发布快照、旧版本删除被拒绝、删除后文件清理与分享失效。
- 本地截图与导出文件：`output/anisong/`（不入版本库）。`match-desktop.png`、`match-mobile.png`、`tier-desktop.png` 和 `tier-export.png` 已人工查看。
- 本次本机预览运行在 `http://127.0.0.1:3129/anisong`，使用独立的 `anisong-dev-db` 容器（仅监听本机55439端口）和测试音频目录 `/tmp/anisong-audio-preview`。这不是生产数据环境，示例曲目均为测试素材。

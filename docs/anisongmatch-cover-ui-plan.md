# AnisongMatch 封面与交互优化

目标：音乐对决同时呈现封面和可播放的音乐，沿用 AniMatch 的布局和交互习惯；修复保存、试听和分享中的边界问题。

## 本轮实施

| 优先级 | 问题 | 实施方案 | 验收 |

| P0 | 对决只有音符，无法辨认专辑或动画 | 歌曲支持封面上传/HTTPS地址；曲单、对决、Tier List、分享和PNG统一携带封面 | 上传、替换、清空、坏图回退；桌面和手机实测 |

3. 批量本地音频导入、试听起点快捷设置和本地标签/内嵌封面提取已实现，见下方第二、三轮记录。后续重点是批量设置动画与参赛范围、曲单备份恢复。

第三方数据接入继续遵循本次会话已有约定，等待用户确定 API 方案。本轮 P0/P1 已实施，验证结果见下方。


## 存储与兼容

- `coverUrl` 为可选字段；旧曲单和旧分享无需数据库迁移，自动显示无封面状态。
- 封面通过 Sharp 解码并统一转为最长边800像素的WebP，限制5 MB输入和2000万像素，不接受SVG或伪造图片。使用现有 `anime_uploads` 持久化卷；音频保持私有。
- 图片地址不可变，旧分享保留原图。删除曲单、移除图片、更新/撤销分享时，清理已无引用的本地封面；失败的上传也会清理文件。
- 上传封面沿用原站公开图片地址的访问方式，不公开音频。外链封面由浏览器加载；如图源限制跨域导出，可改为本地上传。
- 补充修复：仅修改封面且未提交音频字段时保留原音频；上传本地文件可以替换已有音频直链。
- 音量为浏览器偏好，换题后保留；在禁止浏览器存储时仍可播放和调音量。

## 第二轮：本地曲单工作流（2026-10-29）

用户已明确暂不接入 iTunes／网易云 API，本轮只扩展本地音频流程。

### 已实现

- **批量导入**：曲单页新增多文件入口，从文件名填入歌名；`歌手 - 歌名` 格式会拆分字段。导入前可逐首修改，并统一设置类型、年份和季度。
- **导入队列**：逐首上传，显示进度，可在当前请求完成后暂停。失败时停留在队列，已成功项目保留；文件名/大小/修改时间一致的重复选择会跳过，同名同歌手歌曲在提交前提醒。提交前检查64首和250 MB总量限制。
- **恢复与去重**：每项使用固定 `importKey`，首次提交后冻结字段和文件；重试同一编号返回已保存曲单，避免响应丢失后重复新增。每次连续保存使用最新版本，冲突或不完整响应要求重新载入，重载后跳过已保存项。编号只在私有曲单文档中保留，不进入分享快照，无需数据库迁移。
- **保存前试听**：歌曲编辑页可直接播放刚选中的本地文件或已有音源，使用当前位置设置试听起点，快捷选择15/30/60秒，并试听所选片段。界面显示实际音频长度，片段超出尾部时到结尾停止。
- **移除音频**：可清除已保存的音频，保留歌曲、封面和对决记录；保存成功后沿用文件回收逻辑。选择本地音频与填写直链时自动切换当前音源，避免两种来源同时提交。
- **边界修复**：导出PNG期间持有操作锁；导入期间阻止其他修改，离开页面时停止后续队列项目；异常成功响应按“结果未确认”处理。

### 使用边界与后续

- 队列文件只保留在当前页面，刷新或确认离开后需重新选择；已保存歌曲不受影响。去重编号保护同一队列内的重试，重新选择文件仍需核对同名提示。
- 暂停会等待当前上传结束，不撤销已完成项目。每首歌曲的导入独立保存，不是整批回滚。
- 自动读取音频内嵌歌名/封面、批量配图和曲库元数据适配仍待后续；本轮没有新增第三方音源或依赖。
- 本轮完成 TypeScript、ESLint 和生产构建检查。未新增或运行自动化测试；上方37项测试和浏览器检查为第一轮结果，不代表第二轮新增流程已完成浏览器验收。

## 第三轮：本地标签与封面、流程验收（2026-10-29）

### 实现

- 单首和批量导入自动读取本地歌名、歌手及内嵌封面；无标签时回退到文件名。批量列表先展示封面与信息，允许修改歌名、歌手、替换或移除封面，再提交保存。
- 单首添加时，自动信息只填充尚未手动修改的字段。已有歌曲信息和封面受到保护；用户明确移除的封面不会因再次选择音频而自动恢复。
- 标签解析在独立 Web Worker 中运行，每次只处理一首，单文件最多20 MB；10秒超时和“跳过自动读取”都会终止解析线程。切换文件、关闭表单时取消旧读取，旧结果不会覆盖当前输入。
- 读取阶段不上传音频，也不请求音乐平台。封面限制5 MB、2000万像素，优先使用前封面；解码后缩为最长边800像素。解码失败、不支持的图片或浏览器缺少处理能力时回退到手动上传。保存后仍通过原有服务端图片校验。
- 新增固定版本 `music-metadata@11.16.1`，使用其 `parseBlob` 读取文件（[项目文档](https://github.com/Borewit/music-metadata#parseblob-function)）；选择与现有 Node 20 部署配置兼容的版本。此次本机构建运行于 Node 22，未执行生产容器部署。

### 修复

- WAV 的部分 RIFF INFO 标签由写入工具存为 UTF-8、解析器按 Latin-1 读取，中文会乱码。仅在字节序列确认为合法 UTF-8 时恢复编码，保留合法 Latin-1 名称。
- 服务端不再把“有文件名但内容为空”的音频当作未选择音频静默保存。无文件选择仍允许创建无音源歌曲。
- 试听编辑器使用播放请求版本标记，切换源或取消时使旧请求失效，防止迟到的失败回调取消新片段状态。
- 小于1 MB的文件显示 KB，避免有效音频显示成“0.0 MB”；批量替换封面控件沿用站内样式。

### 验收范围

- 第二轮流程已完成真实浏览器验收：批量暂停/续传、统一年份季度、试听片段按设定停止、移除音源、320/390/768像素宽度无横向溢出。

- 42项音乐功能定向测试通过，包含11项元数据/取消/超时测试、4项上传接口/重试测试；TypeScript、ESLint、生产构建通过。

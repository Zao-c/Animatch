# 年度颁奖现场使用与运维

## 主持流程

1. 创建活动：选择群友互助或独立提名；选择链接参与或组织者审核加入。旧活动保留原来的链接参与规则。
2. 群友填写：暂停输入 1.5 秒自动保存草稿。草稿不计票；确认提交后才进入提名汇总。保存失败或版本冲突会暂停自动保存，输入保留在页面，需手动处理。
3. 整理提名：结束征集、核对资格和例外、手动合并别名、选择入围。合并保留原始提交和日志，同一人的重复候选只算一次。
4. 公布入围时保存候选名称、引用和排列顺序快照。旧的已公布活动首次读取时补存快照。
5. 主持台：选择奖项只用于准备；推送入围才切换观众画面。另开 `/screen` 分享给直播软件；群友打开 `/live` 投票。
6. 开票后每人一票，可改选或弃权；关票与投票使用同一活动事务锁，关闭时固定统计。没有有效候选票不能产生投票获奖者。
7. 同票可以并列授奖或仅对并列候选加赛，每轮记录保留。
8. 讨论决定需选择入围候选并填写理由，不制造票数；空缺也必须说明。
9. 确认结果与正式揭晓是两个操作。确认后固定，揭晓不可撤回。年度回顾与 CSV 只包含已揭晓结果。
10. 所有奖项揭晓（含空缺）后可结束本届；刷新或断线重连恢复服务器状态。

本机预览仅展示入围，不改变正式状态，也不产生模拟选票。第一版不包含视频托管、自动播放、OBS 接入或完整流程排练。展示屏需使用已获准参与的登录账号。现场页每 4 秒同步一次。

## 账号升级

共享群邀请码仅用于创建新账号，不能登录已有用户名。每个账号使用独立 scrypt 密码哈希。

- 仍登录的旧账号：在 `/account/security` 设置密码。原有有效登录在设置前继续保留；设置后其他设备的旧会话失效。
- 已退出的旧账号或忘记密码：管理员核实本人身份后，在服务器生成一次性恢复码。恢复码有效 1 小时，使用后立即作废。

```sh
docker exec -it animatch-app node node_modules/tsx/dist/cli.mjs scripts/issue-account-recovery.ts 用户名
```

将恢复码私下交给本人。在登录页展开“注册新账号 / 恢复旧账号”，输入恢复码和新密码。不要把恢复码发到群里或写入仓库。管理员不能仅根据对方提供的用户名确认身份。

现场投票和主持操作要求先设置个人密码。HTTP 部署的传输保护限制仍然存在，密码升级解决的是共享邀请码冒名问题。

## 验证与发布

- `tests/award-live.test.ts`：计票、平票、弃权、草稿、规则及密码哈希。
- `tests/friend-auth.test.ts`：注册、个人密码、拒绝共享邀请码冒名、会话与限流。
- `scripts/check-award-live.ts`：真实 PostgreSQL 权限、并发投票/关票、快照、加赛、保密、讨论、恢复码单次使用。
- 集成脚本只允许 `animatch_award_check_*` 隔离数据库。
- 发布前备份数据库。迁移新增表与列，不删除既有数据。回滚应用时保留新增表，避免丢失现场选票。

候选资格首版采用创建时声明、组织者公布前审核；未自动根据 Bangumi 元数据拒绝年份不符的条目。CSV 分为候选汇总（一候选一行）与提名明细（一支持者一行，不重复附总人数）。

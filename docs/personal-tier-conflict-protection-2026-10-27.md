# 个人 Tier 保存冲突保护（2026-10-27）

## 目标

避免同一份个人自动 Tier List 在多个标签页编辑时，后保存页面静默覆盖先保存的调整。

## 改动

- Tier List 响应包含 `manualTierVersion`，由当前轮次所有作品的手动档位状态及番组 Tier 行配置生成。
- 保存排序和恢复系统排序都必须提交页面读取到的版本；服务端在 Serializable 事务中重新计算并比较版本，冲突时返回 HTTP 409，不写入修改。
- 并发事务冲突也转换为 409。普通对决分数变化不参与版本摘要，不会无关地阻止手动排序保存。
- 页面收到冲突后保留当前排序草稿，并说明服务器版本已更新。用户确认“丢弃本地修改并重新载入”后，才放弃草稿；冲突状态下隐藏普通重载入口，避免先更新版本再意外覆盖。
- 自由排榜的 `ManualTierBoard` 已有独立 revision 校验，本次保护个人自动 Tier List 的编辑流程。
- 无需数据库迁移。

## 检查与限制

- `pnpm exec tsc --noEmit` 通过。
- 针对改动文件运行 ESLint 通过；`git diff --check` 通过。
- 未新增或运行测试，未做浏览器交互验收，也未部署。
- 暂存草稿仍限同一标签页的 `sessionStorage` 能力；本次只保护服务端保存冲突，不提供跨设备草稿同步或自动合并。

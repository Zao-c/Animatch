# 创建番组：重复提交与断网恢复

日期：2026-10-26（北京时间）\
状态：已于 2026-10-26 21:33（北京时间）部署，创建回执迁移已执行。线上检查结果见本文部署记录。

## 1. 问题与修复

| 问题 | 修改 |
| --- | --- |
| 手动创建只改变按钮状态，没有同步锁，快速提交可能发送多个请求 | 共用创建 Hook 增加同步锁；创建期间锁定表单和创建方式切换 |
| 创建已提交，但响应丢失，重试会再建一个番组 | 每次创建使用固定提交编号；服务端保存创建回执，重试返回同一次创建结果 |
| 批量创建失败后改名、改公开设置或改选作品，再点击可能混淆原请求 | 未确认前保留原内容并禁用编辑；提供明确的重试原请求和重新填写入口 |
| 创建完成但跳转未完成，或从详情返回后再次点击创建 | 显示“番组已创建”和进入原番组链接；只有主动选择“创建另一个番组”才开始新的请求 |
| 刷新丢失原提交编号和选中清单 | 同标签页按账号、手动 / 批量方式保存创建记录；恢复后需手动确认，不自动提交 |
| 批量创建已成功，后续封面预热异常却使整个请求报错 | 封面预热不改变已提交的创建结果，页面继续使用原有封面加载回退 |
| 为已有番组批量添加也只有渲染状态锁 | 补上同步锁；沿用已有事务和作品去重逻辑，不纳入新建番组回执 |

## 2. 用户看到的流程

1. 正常填写名称、可见性，批量模式预览并选择作品。
2. 提交后锁定原内容，显示正在确认。
3. 成功后进入对应番组；本地保留已完成入口，返回创建页仍可进入原番组。
4. 请求失败但结果不确定时，显示原番组名称、可见性和批量作品数量，点击“重试并确认原创建”。
5. 同标签页刷新后恢复原内容与编号，不会再次查询 Bangumi 来替换已选作品。
6. 若要放弃本地恢复，先说明这不会删除服务器已创建的番组，也不能取消仍在处理的请求；用户确认后才能开始新请求。

首次提交被明确的 400 / 422 参数校验拒绝时，清理恢复记录后解锁原表单，方便直接改正。后续重试遇到错误仍保留原记录，避免把“本次被拒绝”误认为“上次一定没保存”。

未登录时提示登录；账号在其他页面切换后，服务端会拒绝与预期账号不一致的创建。手动方式有恢复记录时，在创建方式按钮上标注“待确认 / 已创建”。

## 3. 服务端保证的范围

- 新增 `PoolCreationRequest`，以账号和创建编号作为联合主键；记录请求摘要、原番组 ID 和创建结果。
- 请求摘要包含创建方式与内容；同一编号不能用于不同内容。
- 创建番组、批量关联作品、写入创建回执在同一事务内完成。并发冲突时重试或返回可重试提示，失败事务不留下额外番组。
- 重试优先读取原回执，避免原作品后续变化或远程查询结果变化导致再建一份。
- 原番组被删除或不可访问时返回明确提示，保留回执，不因重试而重新创建。
- 已归档但仍属于原账号的番组可返回原入口；不会自动恢复或修改归档状态。
- 新前端都携带编号和预期账号。旧客户端不携带编号的请求保留兼容，但不享受创建去重；部署后应刷新创建页面。
- 不按名称全局去重：用户主动创建另一个同名番组仍然允许。
- 范围包括手动新建和快速导入新建；克隆、示例番组等其他创建入口不属于本批改动。

## 4. 存储与离开页面

- 存储仅用于当前标签页会话，不承诺关闭标签页、清理网站数据或跨设备恢复。
- 存储写入失败会明确提示只能在本页保留请求；服务端仍按本次编号去重。
- 存储读取失败时不自动重发，先提示检查“我的番组”。用户确认开始新请求后，即使本地清理失败，也允许继续本页操作并显示限制。
- 未确认时刷新 / 关闭标签页使用浏览器提示；普通链接离开有确认提示。浏览器前进 / 后退和程序跳转不保证出现提示。
- 页面离开后，迟到的结果不会强行把用户跳回番组；完成记录仅在本地仍是同一编号时更新，避免覆盖后来的新请求。
- 恢复记录包含创建参数与已选作品 ID；不包含登录凭证或 Bangumi 访问令牌。

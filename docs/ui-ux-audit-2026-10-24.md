## 1. 当前结论

用户遇到的主要障碍是：筛选入口和查询能力不完整、封面失败影响选取、异步操作缺少清晰反馈，以及排榜编辑状态不够稳定。本轮已修改相关代码，保持现有深色动画风格。经用户要求，已于 2026-10-24 01:56（北京时间）部署；启动时确认没有待执行的数据库迁移。

这份清单区分三种状态：

- **已改代码**：工作区已有具体实现；不代表所有设备和线上网络均已验收。
- **待修复**：代码中可定位的问题或明确的失败路径。
- **待验证 / 体验建议**：需要实际设备、网络或用户任务验证，不能直接当作已发生的线上故障。

优先级：P1 为影响找到作品、正确保存或继续操作的问题；P2 为效率、可理解性和一致性问题；P3 为细节改进。没有把未证实的问题列为 P0。

### 筛选语义

- “月份”按作品**首播日期**匹配。例如“2026 年 4 月”不包含 5、6 月首播的作品，也不等于整个春季。
- 形式包括 TV、剧场版、OVA / OAD、WEB / ONA、特别篇；恋爱、科幻等内容分类仍通过题材标签筛选。
- 月份要求具体年份。跨年份查找使用高级年份范围，此时不叠加月份。
- 缺少首播日期的条目无法可靠归入某个月；上游元数据不完整仍会影响召回。

## 3. P1：优先继续处理

### U01 — 创建番组时，预览选择与最终导入可能不一致【已改代码，待行为验收】

**10 月 25 日进展：** 用户提交选择后直接使用预览已落库的作品 ID，不再重新远程筛选；所有作品有效性检查、创建番组和写入作品放在同一事务。缺失任意已选作品返回 409，整个创建撤销。以下为原问题记录。

**依据：** [`createPoolFromQuickImport`](../src/lib/import/quick-pool-builder.ts) 再次获取预览候选，然后与用户选中 ID 求交集。只要还剩至少一项就继续；创建番组与加入作品也是分开的步骤。

**用户影响：** 缓存失效或上游结果变化时，可能少导入部分已选作品；后续添加失败时可能留下空番组。

**建议：** 使用有期限的预览快照或稳定候选凭证，提交前检查全部选择的有效性；有差异时明确列出。数据库创建和加入作品应作为一个原子操作，远程抓取放在事务之外。

**验收：** 预览后上游少一项、缓存过期、加入作品失败时，不能无提示地少导入，也不能留下误导性的成功结果。

### U02 — 取消预览只停止前端等待，服务端请求仍可能继续【待修复】

**依据：** [`QuickImportPanel`](../src/components/QuickImportPanel.tsx) 已传递浏览器 AbortSignal；[`requestImportPage`](../src/lib/import/bangumi-import-source.ts) 仍逐页获取并重试，底层请求有 30 秒超时，但没有覆盖整个导入任务的统一截止时间。通用 [`fetchJson`](../src/lib/client-api.ts) 也没有默认总等待期限。

**建议：** 将取消与任务截止时间传入服务端获取流程；大批量预览提供已处理页数 / 数量和部分结果说明。读取与写入操作分别设计超时恢复，写入超时不能直接解释为保存失败。

**验收：** 弱网、429、上游超时后，用户能看到可理解的状态并重新操作；反复取消不会无限堆积后台请求。

### U03 — Match 响应丢失后重试，可能重复记录同一次选择【当前页面重试已改，待行为验收】

**10 月 25 日进展：** 待确认的一票保留原始参数和 mutation ID；网络 / 服务端错误后重试复用 ID，不能直接换一票或撤回；增加“重试上一票”。状态保存在当前页面内，刷新或关闭后的待确认请求恢复仍需后续处理。以下为原问题记录。

**依据：** [个人 Match 页面](../src/app/pools/[poolId]/runs/[runId]/match/page.tsx) 每次调用提交处理器都会生成新的 `clientMutationId`。同步锁已经防止并发点击，但无法处理“服务端已保存，响应没有到达浏览器”的情况。

**建议：** 为一次明确选择保留相同的 mutation ID，网络重试复用该 ID；结果不确定时提供查询确认机制。更改选择或进入下一对时再创建新 ID。

**验收：** 模拟提交成功后断开响应，再重试同一选择，只新增一条有效记录；撤回对应的是用户认为的上一票。

### U04 — 未保存编辑保护没有覆盖完整的离开路径【标签页草稿恢复已改，部分待修复】

**10 月 25-27 日进展：** 自由排榜暂存标题、档位和作品顺序；个人 Tier 暂存作品排序。按账号、番组、轮次隔离，恢复前检查版本及作品集合；服务器变化时明确确认，不自动覆盖。个人 Tier 服务端保存现已使用版本摘要拒绝过期写入，并保留冲突页的本地排序，见 [个人 Tier 冲突保护](personal-tier-conflict-protection-2026-10-27.md)。使用 sessionStorage 支持同一标签页刷新、后退再返回后的恢复，不承诺关闭标签页或跨设备恢复；后退 / 前进新增保护的兼容边界见下。

**依据：** [`use-unsaved-changes`](../src/lib/use-unsaved-changes.ts) 覆盖 `beforeunload` 和链接点击，没有处理 SPA 浏览器后退 / 前进，也没有本地草稿恢复。

**10 月 27 日补充：** 已增加可取消的 SPA 后退 / 前进确认、普通链接重复提示修复及校准按钮离开确认，见 [排榜离开保护](tier-navigation-protection-2026-10-27.md)。本地 Chromium 已检查取消、确认离开与返回恢复；旧浏览器或不可取消导航仍使用标签页草稿恢复。

**建议：** 后续安排 Safari / Firefox 与真实移动设备的返回手势验收，以及多标签保存冲突的浏览器验收。保存冲突时保留本地内容，不能直接覆盖。

**验收：** 后退、前进、刷新、离线保存失败和重新进入页面后，编辑内容可恢复，或有清楚且有效的放弃提示。

### U05 — 图片优化还缺真实用户网络的效果依据【待验证】

**依据：** 本轮优化了候选顺序与卡片交互，既有加载器已有缓存和备用线路；这些不能证明所有地区网络下都足够快。原图和全部缓存副本均不存在时，自动回退也无法恢复图片。

**建议：** 按页面和来源记录加载成功率、首图显示时间、备用源命中率及最终失败数量；用真实移动网络检查作品墙、Match 和导出。所有源失败时提供清楚的修复封面入口，避免持续等待。

**验收：** 单个来源失效时仍能继续选作品；能区分缺图和网络失败；真实弱网数据可用于判断下一步应改缓存、来源还是并发策略。
